# 🔮 실외 PM2.5 3시간 예측 (pm_predict)

AirClass의 **사전대응**을 위한 실외 미세먼지(PM2.5) 예측 모듈임.
지금까지의 공기·기상 정보로 **3시간 뒤 PM2.5**를 예측해, 나빠지기 전에 환기·공기청정기 계획을 세울 수 있게 함.

## 1. 문제 정의

- **예측 대상**: 3시간 뒤 실외 PM2.5 (㎍/㎥)
- **핵심 목표**: 지금은 괜찮지만 **3시간 안에 나쁨(36↑)이 되는 순간**을 미리 잡는 것
- **3시간을 선택한 이유**: 1시간 뒤는 현재값과 거의 같아(오차 3.1, ±10 이상 변화 5.4%) 예측 의미가 적고, 6시간 이상은 공식 예보가 있음. 3시간은 변화가 충분하고(±10 이상 15%) 쉬는 시간 2~3번으로 미리 대응할 수 있음.

## 2. 데이터와 전처리

| 구분 | 출처 | 내용 |
|---|---|---|
| 대기질 | 에어코리아 최종확정 측정자료, 2022~2025 시간별 | PM2.5, PM10, O₃, NO₂, CO, SO₂ |
| 기상 | 기상청 AWS 565 시흥, 2022~2025 시간별 | 기온, 풍향, 풍속, 강수, 습도 |

**전처리**
- 대기질 24시를 다음 날 0시로 바꾸고, 시각 기준으로 대기질에 기상을 병합함.
- 정답은 채우기 전 **원본 PM2.5**(`target_pm25`)를 사용함.
- **3시간 이하 빈칸만** 선형 보간하고, 긴 빈칸(매년 3월 정기 점검 등)은 그대로 둠. 풍향은 각도라서 직전 값으로, 강수는 채우지 않음.
- 풍향은 `sin/cos`와 풍속을 반영한 바람 벡터(`wind_u`, `wind_v`)로 변환함.

**데이터 특이사항**
- PM2.5 = 0 (710개)은 깨끗한 날의 측정 하한값이라 유지함.
- 1시간에 40 이상 급변한 32건은 PM10·CO가 함께 움직여 **실제 국지 배출 사건**으로 판단하고 유지함. 3시간 전 예측이 어려운 구간임.
- 최근으로 올수록 깨끗해짐(나쁨 비율 Train 15.0% → Valid 8.9% → Test 10.3%). 결과 해석 때 고려함.

## 3. 모델 비교 계획

**Linear Regression을 기준 모델로 학습·평가하고, 이후 ARIMA, LightGBM, LSTM과 성능을 비교함.**

| 단계 | 모델 | 특징 | 상태 |
|---|---|---|---|
| 0 | 현재값 유지 | "3시간 뒤 = 지금". 모든 모델이 넘어야 할 최소 기준 | ✅ |
| 1 | **Linear Regression / Ridge** | 직선 관계만 학습. 이후 모델을 비교하는 **기준 모델** | ✅ |
| 2 | ARIMA / SARIMAX | AR 구조를 직접 모델링하는 통계 모델. 기상은 외부 변수로 사용 | ⏳ |
| 3 | LightGBM | 비선형·조건 조합 학습, 변수 중요도로 설명 가능, 라즈베리파이 추론에 적합 | ⏳ |
| 4 | LSTM | 최근 24시간 시퀀스를 그대로 입력하는 딥러닝 비교 모델 | ⏳ |

## 4. 시계열 특성과 차분

| 모델 | 정상성 가정 | 계절성 처리 |
|---|---|---|
| ARIMA / SARIMAX | 필요 | **차분** (계절 차분 s=24, 연 주기는 푸리에 항) |
| Linear Regression, LightGBM | 없음 | **특징** (시각·월 sin/cos, lag, 이동평균) |
| LSTM | 없음 | 시퀀스에서 스스로 학습 |

- **계절성이 있다고 반드시 ARIMA를 쓸 필요는 없음.** 차분은 ARIMA의 전제 조건이고, 처리 방법은 모델마다 다름. 이 데이터는 계절 주기가 둘(하루·1년)이고 급변이 외부 요인에서 비선형으로 오며 분포가 치우쳐 있어(왜도 1.75) ARIMA에 불리함.
- **ACF·PACF**: PACF가 lag 1(0.94) 이후 급격히 0이 되는 AR(1)형 구조임. 다만 장기 ACF가 AR(1) 기대보다 높아(24시간: 0.45 vs 0.23) 천천히 변하는 배경 수준이 있음 → lag 1~3 + 6·24시간 이동평균 사용.
- **목표값 차분**: 트리 모델은 학습 범위 밖 값을 예측하지 못해서, LightGBM은 "3시간 동안의 변화량"을 예측하고 현재값을 더해 복원하는 방식도 비교함. 평가는 복원한 값으로 함.
- STL 분해와 ADF·KPSS 검정으로 계절성과 정상성을 추가 확인할 예정임.

## 5. 검증과 평가

- **시간 순서 분할**: Train 2022~2023 / Valid 2024 / Test 2025(마지막에 한 번만 평가). 경계 3시간은 제외함.
- 무작위 K-Fold는 이웃 시간끼리 정보가 새서 사용하지 않음. 필요하면 `TimeSeriesSplit`을 추가함.
- 모든 모델을 **같은 행·같은 특징·같은 평가 함수**로 비교하고, 특징 그룹을 하나씩 추가하며 기여도를 확인함.

| 지표 | 의미 |
|---|---|
| MAE / RMSE | 전체 오차 |
| 큰 변화 MAE | 3시간 동안 ±10 이상 변한 시점의 오차 (모델 실력이 드러나는 곳) |
| 전환 재현율 / 정밀도 | 나쁨 전환을 미리 잡은 비율 / 경보가 맞은 비율 (**사전대응 핵심 지표**) |

**이후 계획**: 회귀 모델은 전환을 잘 잡지 못할 수 있어 **"3시간 안에 나쁨이 될 확률"을 예측하는 분류 모델**을 함께 검토함. 1·2·3시간을 각각 예측해 앱에서는 흐름을 보여 주고, 경보는 3시간 기준으로 울림.

## 6. 지금까지 결과 (Valid 2024)

| 모델 | MAE | RMSE | 큰 변화 MAE | 전환 재현율 | 전환 정밀도 |
|---|---|---|---|---|---|
| 현재값 유지 | 4.94 | 7.55 | 16.00 | 0.000 | 0.000 |
| Linear Regression | 4.74 | 7.01 | 13.98 | 0.011 | 0.429 |
| Ridge | 4.74 | 7.01 | 13.98 | 0.011 | 0.429 |

선형 모델은 전체 오차를 약 4% 줄였지만 **나쁨 전환은 거의 잡지 못했음**(재현율 1.1%).

## 7. 파일 구성과 실행

| 파일 | 내용 |
|---|---|
| `config.py` | 경로, H=3, BAD=36, MAX_GAP=3, FEATURES |
| `data_loader.py` | 데이터 불러오기, DataFrame화 |
| `preprocess.py` | 병합, 결측 처리, 풍향 변환, 중간 저장 |
| `eda.py` | EDA 그래프 (`outputs/eda/`) |
| `features.py` | 특징 만들기 |
| `split.py` | Train/Valid/Test 분할 |
| `evaluate.py` | 평가 함수 |
| `linear_model.py` | 기준선 + Linear Regression / Ridge |

```bash
cd pm_predict
pip install -r requirements.txt
python data_loader.py     # 불러오기 확인
python preprocess.py      # 전처리 → iot_dataSet/iot_preprocessed.pkl
python eda.py             # EDA 그래프 → outputs/eda/
python linear_model.py    # 기준선·선형 모델 결과
```

원본 데이터는 `iot_dataSet/air/연도/`, `iot_dataSet/weather/연도/`에 두면 됨 (깃에는 올리지 않음).
